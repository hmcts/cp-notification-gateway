§ 02 · Pattern & ownership

Why MbD, what it owns

Rubric bucket: MbD event-processor / integration service, thin-stateful. The legacy CQRS/event-sourcing existed only to drive async tasks — a role cp-task-manager now fills — so the event store is dropped (no new WildFly/Java EE service). The service owns the notification table end-to-end; the cp-task-manager jobs table is co-located in the same datasource so INSERT-row + enqueue-task commit in one local transaction. No cross-context DB reads — integration is ASB messages plus one cross-context Blob read.

Invariant: exactly-once observable effect under at-least-once delivery — one row, one send, at most one result event — enforced by PK dedupe on ingest and a state-transition guard on every terminal transition and result publish.

§ 04 · Parity & failure taxonomy

Preserved behaviour (NFR-001)

  • Result events byte-for-byte to the golden-master: sent = verbatim copy (needs subject/body/replyTo from the Notify response); failed = hand-built, drops failedTask, omits absent optionals; additionalProperties:false. Schemas in-repo under contracts/, additive-only.
  • Retry list 60,300,1800,3600,7200,14400 via cp-task-manager getRetryDurationsInSecs().
  • Error taxonomy ported verbatim from legacy FailureSelector: permanent = HTTP 400 / 413, Blob 403/404; transient = HTTP 500, status-0 with known messages, and any non-permanent default.
