Implementation Plan · NG-S03 · PEG-3382

ReplyTo-gated result event with legacy golden-master parity

Turn the RED NG-S03 suite GREEN: when a notification reaches a terminal state and its persisted result_queue is set, publish a notification-sent/notification-failed result event — payload matching the legacy cpp-context-notification-notify golden master exactly — to that reply queue. When result_queue is null (mi-reportdata MVP) the send completes silently. Routing is read back from the row already loaded by the terminal state guard; the two contracts live in-repo under contracts/ and are enforced by a schema-diff test.

1

Result-event payloads (golden master)

BuildAC-016
Two immutable, Jackson-serialised value types whose on-the-wire JSON is byte-for-byte the legacy contract: required fields always present, optionals omitted (not null), no extra fields.
  • result/ResultEvent — sealed interface exposing eventName() so the publisher can set the ASB subject polymorphically
  • result/NotificationSentEvent — EVENT_NAME + builder; verbatim copy of the internal event (notificationId/sentTime required; completedAt/sendToAddress/replyToAddress/emailSubject/emailBody/clientContext when present)
  • result/NotificationFailedEvent — EVENT_NAME + builder; hand-built notificationId/failedTime/errorMessage, adds statusCode/clientContext only if present, drops failedTask
  • @JsonInclude(NON_NULL) on both — absent optionals are omitted, honouring additionalProperties:false
Jackson 3 (tools.jackson): built-in java.time support serialises OffsetDateTime as ISO-8601 (WRITE_DATES_AS_TIMESTAMPS=false default). Annotations still come from com.fasterxml.jackson.annotation. eventName() is not a bean getter so it is not serialised.
2

Result-event publisher (ReplyTo routing + gating)

BuildAC-014/015
A thin ASB sender that routes a result event to a named reply queue, subject = event name, body = golden-master JSON — and no-ops when the queue is blank.
  • result/ResultEventPublisher — (connectionString, namespace, ObjectMapper); same credential switch as ServiceBusConfig (connection-string → emulator/local; else DefaultAzureCredential)
  • publish(queueName, ResultEvent) — blank/null queueName → return (AC-015); else send ServiceBusMessage with subject = event.eventName()
No secrets, no SAS/keys. Emulator connection-string is a local-test-only value injected via @Value; real envs use Managed Identity via the namespace branch.
3

Terminal hop wiring (read-back from the row)

BuildAC-014/015 · NFR-009
The terminal state guard already loads the row; build + route the result event right there from persisted fields — never from job_data or the original message.
  • service/NotificationStatusService — inject ResultEventPublisher; after markSent/markFailed save, publish from the loaded entity (result_queue, sendToAddress, clientContext, statusCode, errorMessage, updatedAt → sent/failed time)
  • Update NotificationStatusServiceTest — add the publisher collaborator and assert publish-on-set / no-publish-on-null (AC-014/015 at unit level)
Idempotency (NFR-009): at most one event per notification — the NG-S12 state-transition guard (out of scope here) fronts the terminal transition, so a re-run does not re-enter markSent/markFailed and does not re-publish.
