Implementation Plan · NG-S02 · PEG-3372

Core email send — ASB ingest → blob → Gov.Notify → SENT

Turn the RED NG-S02 suite GREEN: consume send-email-notification from the shared ng-send-email queue, persist an atomic QUEUED row + SEND_EMAIL job, download the attachment from Azure Blob, send via Gov.UK Notify, then poll CHECK_EMAIL_STATUS to drive the row to SENT. Credential switches (blob + ASB) let the same code run on Azurite/emulator locally and Managed Identity in AKS.

4

Task orchestration & terminal state

PlanAC-011/012/013 · FR-010
The cp-task-manager tasks stitch the boundaries together and drive the row terminal; retry cadence preserved byte-for-byte.
  • task/SendEmailTask (@Task("SEND_EMAIL")) — download → route → send → schedule CHECK_EMAIL_STATUS (reference in job_data). Permanent blob fail → markFailed + COMPLETED (no retry)
  • task/CheckEmailStatusTask (@Task("CHECK_EMAIL_STATUS")) — DELIVERED → markSent + COMPLETED; else INPROGRESS + shouldRetry (re-poll)
  • service/NotificationStatusService — markSent(id) / markFailed(id, statusCode, errorMessage)
  • Both tasks return getRetryDurationsInSecs() = [60,300,1800,3600,7200,14400]
cp-task-manager has no FAILED state (STARTED/INPROGRESS/COMPLETED only): a permanent failure marks the notification FAILED and settles the job COMPLETED — never a throw-loop.
